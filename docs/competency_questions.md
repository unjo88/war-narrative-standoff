# 온톨로지 검증 질의(competency questions)

발표문 Ⅲ장 2절은 온톨로지를 "그것으로 답할 수 있는 질문"으로 검증한다. 질문과 답은 코드가 공개 데이터에서 직접 계산해 `aggregates/competency_questions.csv`에 기록하며, 자동 검사(`tests/test_repo.py`)가 발표문의 서술과 일치하는지 확인한다.

| ID | 질문 | 답의 근거 |
|---|---|---|
| Q1 | 1597년에 상실 범주의 정서어가 잡힌 날짜는? | `pilot_1597_records.csv`의 v1_상실 > 0 |
| Q2 | 명량해전(9.16) 이후 30일 안에 나타난 정서는? | 9.17–10.16 레코드의 범주별 개수 |
| Q3 | 정유일기Ⅰ·Ⅱ에서 주된 정서 범주가 갈리는 날짜는? | `overlap_1597_I_II.csv`의 top_category_I ≠ top_category_II |
| Q4 | 18권 22–35행에서 두 번역의 정서 범주는 일치하는가? | `witness_deviation_examples.csv` |

## 읽는 법
- 답은 **사전 v1 자동 태깅** 결과이므로 오탐을 포함한다. Q3의 7일 가운데 8.7·8.10은 오탐, 8.9는 다른 사람(낙안 고을 사람들)의 정서 때문에 갈린 것으로, `note` 열에 적었다.
- 오탐이 질의 결과까지 바꾼다는 점은 발표문이 말하는 '정제는 해석이다'의 구체적 사례다. 동형어 사전과 행위자 태그를 반영한 뒤 같은 질의를 다시 돌려 답이 어떻게 바뀌는지 비교하는 것이 전체 구축의 검증 절차다.
- 질의를 RDF 그래프(SPARQL)로 옮기는 작업은 전체 데이터를 온톨로지 인스턴스로 변환한 뒤 진행한다. 현재 `ontology/war_narrative.ttl`에는 클래스·관계와 예시 인스턴스만 있다.
